Description

Structure and crack messy, ambiguous, or consequential problems using the
Conn & McLean 7-step method. Use whenever a problem is vague, has multiple
moving parts, or where the right question isn't yet clear - strategy
questions, resource allocation, "how should we think about X," or any
request where jumping to an answer risks solving the wrong problem well.
Also fires on explicit invocation: "run this through the 7 steps,"
"disaggregate this," "give me a MECE tree," "what's the one-day answer,"
"what assumption am I making."

Instructions
Apply the 7-step Bulletproof Problem Solving method. Scale rigor to stakes -
a small or reversible call gets the 10-minute version, not the full engagement.

FIRST, ALWAYS: name the assumption buried in the question, and check the
framing. If the question is a false binary or scoped so narrowly the
interesting answer is excluded, say so before proceeding.

1. DEFINE THE PROBLEM
   State: decision-maker, success measure, what's in scope AND explicitly
   out, constraints, timeframe, and required accuracy (directional enough
   to allocate effort, or audit-grade? - this silently determines how much
   work everything else needs).

2. DISAGGREGATE - build a MECE logic tree
   Mutually exclusive, collectively exhaustive. Choose the tree type:
   - Factor/lever tree - problem decomposes mathematically (X = A x B)
   - Deductive/component - split by structure (segment, product, geography)
   - Hypothesis tree - candidate explanations, branch each
   - Decision tree - options, outcomes, payoffs
   - Inductive - build up from observations to patterns
   Test it: any overlap? anything missing? Could someone else using this
   tree land in the same places? A branch that can't be tested or acted on
   is decoration.
   THIS IS THE HIGHEST-VALUE STEP. Most "hard" problems are one aggregated
   instruction hiding three sub-problems with different owners and different
   answers. Never analyze a lump.

3. PRIORITIZE - prune hard
   Score branches on impact x ability to influence. Only high-impact +
   high-control is real work. Say explicitly what you're setting aside and
   why - silent pruning looks like an oversight later.

4. WORKPLAN
   Per surviving branch: what analysis, who owns it, by when, and what it
   would confirm or kill. An analysis that can't change a decision doesn't
   belong.

5. ANALYZE - heuristics first
   Summary statistics, back-of-envelope, rules of thumb, base rates.
   Occam before the big guns. Escalate to heavy machinery only when a
   specific decision hinges on the precision. Building the detailed model
   first is usually procrastination wearing a lab coat.

6. SYNTHESIZE
   Build an argument, not a list. Ask "so what?" until you reach something
   someone would act on.

7. COMMUNICATE
   Governing thought first, then support. For exec-facing: Situation /
   Complication / Resolution. Close with "what would change this answer."

GIVE THE ONE-DAY ANSWER EARLY
State your best hypothesis plainly, labeled as a hypothesis, with what would
confirm or kill it and what to test first and cheapest. Don't wait for
completeness to have a point of view.

BIAS GUARDS - run against your own output
- Confirmation bias: what would disconfirm this? Go look for that first.
- Anchoring: whose number is in my head, and where did it come from?
- Inside-view overconfidence: base rate before the story of why this is special.
- Premature hypothesis lock: the one-day answer is a hypothesis, hold it loosely.
- Motivated reasoning: am I building the case for the answer authority wants?
- Analyzing the lump: if a recommendation can't be assigned an owner, it's
  still aggregated.

Deeper reference if loaded: "Bulletproof Problem Solving - Method" and the
worked exemplar "Owl Value-Creation Strategy - Bulletproof Problem-Solving
Engagement."
